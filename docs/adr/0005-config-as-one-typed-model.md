# ADR-0005: One typed configuration model with generated projections

- **Status:** Accepted
- **Date:** 2026-08-02
- **Relates to:** `CFG-001`–`CFG-003`, `CFG-010`–`CFG-013`, `CFG-020`–`CFG-040`, `UI-002`

## Context

Java CDM's configuration is a `KnownProperties` enum of ~90 string keys with a parallel
`cdm-detailed.properties` reference file, a parallel README table, and a parallel React config
builder with its own copy of the rules. Four representations of the same knowledge, kept in sync by
hand. Predictably they drift, and validation happens at runtime — sometimes hours into a job.

## Decision

Define configuration **once**, as a typed Rust struct tree with a `CdmProperties` derive macro
carrying the legacy alias, default, unit, secrecy, stability and documentation for each field.

Everything else is generated from it:

| Artefact | Generated by |
|---|---|
| Java `spark.cdm.*` alias table | `CdmProperties` derive |
| `schema/cdm-config.schema.json` | `schemars` |
| OpenAPI component schemas | `utoipa` |
| `docs/generated/PROPERTIES.md` | `cargo xtask docs` |
| `clap` CLI flags | `CdmProperties` derive |
| Web UI form descriptors | the JSON Schema |

Validation runs in three tiers before any data moves: syntactic, semantic (cross-field), and
schema-bound (against the live cluster). All violations are reported at once, each as a `Diagnostic`
with the offending key, the value, the rule and a suggested fix.

## Consequences

**Positive.** Drift becomes impossible — CI fails if any generated artefact is stale. Configuration
errors surface in seconds instead of hours. The UI, CLI and API validate identically because they
share one implementation. Plugins contribute config keys that flow automatically into every artefact
(`PLG-013`).

**Negative.** A proc-macro to write and maintain, and the derive is a compile-time cost. Both are
paid once.

**Compatibility.** The `.properties` loader accepts the full Java namespace, so existing configs run
unchanged (`S2`). Unknown `spark.cdm.*` keys warn with a Levenshtein suggestion rather than failing,
unless `--strict-config` is set. Non-`cdm` `spark.*` keys are ignored silently, since they are Spark
tuning that no longer applies.
