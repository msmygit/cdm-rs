# `scripts/`

Repository maintenance helpers. These are developer conveniences, not part of the `cdm` binary and
not on any release path.

---

## `reclaim-agent-space.sh`

Reclaims disk taken by coding-agent git worktrees under `.claude/worktrees/`.

### Why this exists

Coding agents (Claude Code and similar) run in throwaway git worktrees so that parallel work cannot
collide. Each worktree compiles its own `target/` directory, which for this workspace is **2–12 GiB**
of dependencies, debug symbols and incremental-compilation cache.

The source in a worktree is about 5 MB. Essentially all the space is build output. A dozen finished
agents will therefore consume tens of gigabytes for nothing, and the failure is indirect: builds
start failing, or an agent stops midway, and the cause is not obvious from the error. During
development of this repository, agent worktrees reached **98 GiB against 1.0 GiB of free disk**, and
one agent hit a zero-byte root volume mid-run.

Everything the script deletes is regenerated by `cargo build`. The cost of running it is rebuild
time and nothing else.

### Usage

```bash
just reclaim                    # report what could be reclaimed; changes nothing
just reclaim-apply              # reclaim the safe candidates
just reclaim-apply --all        # also include unmerged or dirty worktrees
just reclaim-apply --prune      # additionally remove worktrees that are merged and clean

scripts/reclaim-agent-space.sh --help
```

Or call it directly, which is the same thing:

```bash
scripts/reclaim-agent-space.sh                        # dry run
scripts/reclaim-agent-space.sh --apply
scripts/reclaim-agent-space.sh --apply --all --prune
scripts/reclaim-agent-space.sh --idle-minutes 30      # widen the "is it building?" window
```

### What it will and will not touch

It removes **only directories named `target`** inside `.claude/worktrees/*/`. Not source, not git
history, not branches, not `settings*.json`, not anything under `~/.claude`.

`~/.claude` is deliberately out of scope: it holds session transcripts and totals well under
100 MB, so deleting from it is destructive for no meaningful gain.

A worktree is **skipped** when:

| Condition | Reason | Override |
|---|---|---|
| Something under `target/` changed in the last 20 min | An agent is probably building in it | `--idle-minutes N` |
| Its branch is not merged into `origin/main` | May still be needed for a rebase or re-verification | `--all` |
| It has uncommitted changes | May hold the only copy of that work | `--all` |
| It is not a git worktree at all | Leftover directory; a human should look at it | none — always skipped |

Deleting `target/` is safe regardless of git state, since it contains no source. The unmerged and
dirty checks are about *convenience* — you probably want to keep a build directory you are about to
need again — whereas the activity check is about *correctness*: deleting a build directory out from
under a running agent will not corrupt anything, but it will throw away work in progress and can
fail that agent's run.

`--prune` is the only genuinely destructive option, because it removes the worktree itself. It
applies only to worktrees that are both merged **and** clean. The branch and its commits survive
worktree removal in any case; `git worktree list` and `git branch` will show what remains.

### Reading the output

```
  agent-a94bad0a2266191ff             merged      7.7G  SKIP: active: written to in the last 20m
  agent-aea0a45a3be031552             unmerged     12G  would remove
  agent-a02d91bb32f70e1e4             merged    already clean

Build directories found:       42.9 GiB
Reclaimable by this run:       12.4 GiB
Worktrees skipped:             5
```

Columns are: worktree, merge state against `origin/main`, size of its build directory, and the
action. In a dry run the action reads `would remove`; with `--apply` it reads `REMOVED`.

### Suggested habit

Run the read-only report before launching a batch of agents, and budget roughly **8 GiB per
concurrent agent**:

```bash
just reclaim && df -h /
```

Automating the deletion — on a hook or a timer — is not recommended. It would eventually fire while
an agent is mid-build, and the activity window is a heuristic rather than a guarantee, so the
failure would be silent and confusing. Agents working in this repository are instructed to remove
their own `target/` once their pull request is open; this script is the backstop for the ones that
are interrupted before they get there.
